# Feature Specification: Reading C4, Databricks, Wardley Map and Turtle Through Declared Bindings on the Desktop

**Feature Branch**: `features/067-desktop-fbl-bindings`

**Created**: 2026-10-31

**Status**: Draft

**Input**: Peter chose, on 2026-10-30, that the tool descriptions of spec 035 read their formats through declared FBL bindings rather than by wrapping each module's reader as a capability. This feature is the desktop host's part of that choice, for the formats whose bindings exist.

## Context

Spec 035's tool descriptions are meant to replace the desktop host's hand-written modules, and its T132 asks that every conformance case passes on the description alone. On 2026-10-30 almost none did: `atd validate` passed 2 of about 260 cases.

Three causes were found, and each is checked against the state of `develop` that day:

1. **The reader capabilities are missing.** 19 descriptions name a binding `family capability reader.*`, and the desktop runtime provides none of those readers, so their documents open read-only. The readers are not code that can be moved: most modules open their documents themselves, outside FBL's persistence plugin contract.
2. **The desktop host stops at FBL 0.9.** Spec 066 took FBL to 0.13 so that Structurizr, Databricks and the Wardley map can be declared bindings, and it left each host to follow "under their own FBL specifications". This is that specification for the desktop. Of the 56 fixtures those versions added, 1 runs on the desktop today; the rest are named as not supported.
3. **Recorded gestures speak the modules' language.** Many case steps name a module's action and a target string only that module understands, such as `dependencies.connect` with the target `rel:a->b`, or `dependencies.add-element` with `new:300,0`. A description's own tool has no such action, so the step is refused however good the binding is.

The formats fall into three groups:

| Format | Descriptions | State | This feature |
|---|---|---|---|
| Structurizr DSL | the six C4 types | a declared binding exists (`structurizr.fbl`) | bound (story 2) |
| Databricks YAML and JSON | bundle, job, pipeline | declared bindings exist | bound (story 2) |
| Online Wardley Maps | Wardley map | a declared binding exists (`wardley-map.fbl`) | bound (story 2) |
| Turtle | RDF, OWL, SHACL, SKOS | a partial grammar binding exists (`w3c-turtle-grammar.fbl`); FBL cannot yet state the rest | FBL extended, then bound (story 4) |
| SPARQL, Ansible, Helm, Azure Pipelines, MSBuild | one each | a plugin reader only | not this feature |

### What this feature is not

- **Not the whole of T132.** Descriptions outside the table's first four rows stay as they are, and so do the differences of the descriptions that do not depend on a reader, except where story 3 removes them.
- **Not retiring the modules.** A person who opens a document keeps today's tool (spec 035, story 4 scenario 4). The modules stay the reference the cases were recorded from.
- **Not the other hosts.** Standalone, VS Code and IntelliJ follow FBL under their own specifications.
- **Not a change to what the cases expect.** A case's expected bytes, readings, findings and drawings are the reference and do not change to suit a description. Only how a gesture is written in a step changes (story 3), and a case states which host kind recorded it (FR-012).

## Clarifications

### Session 2026-10-30

- Q: Is a refusal's wording compared when the host wrote it rather than the description? → A: Only a description's own reason is compared exactly; the host's sentence that a gesture is not offered counts as the same refusal (Peter, 2026-10-30; FR-011).

### Session 2026-10-31

Found while running the C4 descriptions on their binding: their bytes matched on every step, yet no case could pass.

- Q: How is a case's reading and drawing compared for a tool whose module opens its own documents? → A: By what is meaningful: a reading by ids, parents, ends and values, a drawing by which elements appear and where. Bytes stay exact, and no expected result changes (Peter, 2026-10-31; FR-012).
- Q: What can a rule about the model see of a view, given a reading holds only its own view's statements? → A: Every view, with its members: `diagram.views` is implemented, and a reading keeps each view's statements as data (Peter, 2026-10-31; FR-013).
- Q: Does FBL's Structurizr example change where the module differs from it? → A: Yes: `structurizr.fbl` takes `place: end` and `empty: keep` (Peter, 2026-10-31; FR-014).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - The desktop host reads and writes everything FBL states (Priority: P1)

A tool engineer writes a binding using any construct of the current FBL version, and the desktop host reads and edits a document through it exactly as FBL says and as the standalone host does.

**Why this priority**: every other story stands on it. A binding the host cannot run cannot replace anything.

**Independent Test**: run FBL's fixtures on the desktop host; none of those added by FBL 0.10 and later is named as not supported.

**Acceptance Scenarios**:

1. **Given** one Databricks file and a rule with `origins`, **When** the file is read as a job and as a pipeline, **Then** each reading holds only the elements of its own tool type (FBL 0.10).
2. **Given** a Structurizr workspace with comments after braces, escaped quotes and a missing closing brace, **When** it is read, **Then** the elements, values and findings are those of its fixture, and the body stays editable (FBL 0.11).
3. **Given** a Wardley map with duplicate names and an identities file, **When** a component is renamed, **Then** the body and the identities file change together in one edit, and one undo restores both byte for byte (FBL 0.12).
4. **Given** one quoted argument holding `"Extra, More"` under a slot that splits, **When** it is read, **Then** the attribute holds two tags (FBL 0.13).
5. **Given** a fixture whose splices name several files, **When** it is replayed, **Then** each file's bytes are as the fixture states.

---

### User Story 2 - C4, Databricks and Wardley map descriptions run on declared bindings (Priority: P1)

A tool engineer validates a C4, Databricks or Wardley map description, and its documents open editable through the description's own binding, with no reader capability and no module code.

**Why this priority**: these 10 descriptions hold 137 of the cases, and their bindings are already written.

**Independent Test**: `atd validate` on each of the 10 descriptions; none reports that a document could not be read, and each reading equals the case's.

**Acceptance Scenarios**:

1. **Given** a C4 description, **When** a case is run, **Then** its document is read through a `family grammar` binding and its reading equals the case's.
2. **Given** the description requires a layout capability the case's drawing depends on (`layout.rankedBoundaries`, `layout.layeredColumns` or `layout.bands`), **When** the case is run, **Then** the host provides it, its own capability fixtures passing, and the drawing's positions equal the case's.
3. **Given** the Wardley map description, which today does not lower, **When** it is validated, **Then** it lowers and its cases run.

---

### User Story 3 - A recorded gesture is one any description can replay (Priority: P2)

A tool engineer replays a case, and every step is written in ATD's own terms (§2.3), so that it means the same to the description's tool as it did to the module it was recorded from.

**Why this priority**: without it, a correct binding still fails on every step that connects, creates or disconnects, and later steps fail in turn. It is needed for story 2's cases to pass, and it helps every other description.

**Independent Test**: no step of a recorded case names a module's target string, and `atd record --check` still holds for every case.

**Acceptance Scenarios**:

1. **Given** a parity script that connects two nodes through a module's action, **When** the case is recorded, **Then** the step is a `connect` naming its two ends, and its expected result is unchanged.
2. **Given** a parity script that creates an element at a point, **When** the case is recorded, **Then** the step is a `create` naming its type and place, and its expected result is unchanged.
3. **Given** a gesture that ATD's steps cannot state, **When** the case is recorded, **Then** recording says so by naming the gesture, rather than writing a step no description can replay.

---

### User Story 4 - Turtle is read through a declared binding (Priority: P3)

A tool engineer validates the RDF, OWL, SHACL or SKOS description, and its Turtle is read and written through a grammar binding with no persistence plugin, which settles spec 035's T149.

**Why this priority**: it covers four descriptions and about 90 cases, but it needs FBL itself to grow first, unlike story 2.

**Independent Test**: `atd validate` on the four descriptions with no reader capability registered; new FBL fixtures for each construct added pass on the desktop host.

**Acceptance Scenarios**:

1. **Given** `foaf:name "A"` under `@prefix foaf: <http://…>`, **When** it is read, **Then** the element carries the full IRI the prefix gives it.
2. **Given** a predicate-object list inside a subject's statement, **When** a triple is read, **Then** it reaches its subject in the statement around it.
3. **Given** blank nodes in a statement, **When** the body is read twice, **Then** each has the same ordinal both times.
4. **Given** a literal holding an escape, **When** it is read and written back, **Then** the value is unescaped and the untouched bytes are kept.
5. **Given** a triple is inserted or removed, **When** the case's step runs, **Then** the bytes equal the recorded host's.

### Edge Cases

- A document one version of a binding reads and another refuses: the finding names the construct, as FBL states.
- A case whose expected result records a quirk of the module, such as the mind map's indicator not drawn again after an undo: the case stays, and the difference is listed by name until someone rules on it. It is never removed by editing the case.
- A case whose binding depends on a capability outside this feature: it reports `ATD9010`, and it counts as not yet in scope rather than as failing.
- A fixture added to FBL while this feature is under way: it is run, or named as not supported with its reason.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: The desktop host MUST implement FBL through the version current when this feature's plan is written, with the same bytes as the standalone host for the same edit.
- **FR-002**: The desktop host's conformance run MUST run every fixture of FBL 0.10 and later, including those whose edits span several files, and MUST NOT name any of them as not supported at the end of this feature.
- **FR-003**: The six C4, three Databricks and one Wardley map descriptions MUST bind their bodies with declared rules, and MUST NOT require a reader capability.
- **FR-004**: The desktop host MUST provide `layout.rankedBoundaries`, `layout.layeredColumns` and `layout.bands`, each passing its fixtures, with today's tools drawing exactly as before.
- **FR-005**: Recorded case steps MUST state gestures in ATD §2.3's terms and MUST NOT carry a target string that only a module understands.
- **FR-006**: Changing how a gesture is written MUST NOT change any step's expected bytes, reading, findings or drawing.
- **FR-007**: A gesture ATD cannot state MUST be named when a case is recorded. Whether ATD gains a step for it is decided case by case.
- **FR-008**: FBL MUST gain what Turtle needs, each construct with its fixture and its schema, as a minor version: reaching a statement's subject from a triple inside it, expanding a prefix, stable blank-node ordinals, and unescaping a literal.
- **FR-009**: The RDF, OWL, SHACL and SKOS descriptions MUST bind Turtle with the grammar family and pass their cases with no persistence plugin, including Turtle cases with inserts and removals recorded from the desktop host's reader (spec 035, T149, FR-082, SC-010).
- **FR-010**: A person who opens a document MUST keep today's tool, and validating MUST write no file of the description or the case.
- **FR-011**: Comparing a refusal, a reason the description wrote MUST match exactly. The host's own sentence that a gesture is not offered, such as "Unknown action 'x'." or "'x' does not apply to this selection.", MUST count as the same refusal whatever its wording, and ATD §2.3 MUST state this.
- **FR-012**: A case recorded from a module that opens its own documents MUST say so, and `atd validate` MUST then compare its reading by ids, parents, ends and values, and its drawing by which elements appear and where they are, in place of comparing the module's own type names, wire attributes, shapes and painted chrome. Bytes, splices, findings and refusals MUST stay compared as before, and a case recorded from a declared tool MUST stay compared exactly.
- **FR-013**: `diagram.views` MUST be available to a rule, listing every view of the body with its members, whichever view the reading shows, and a reading MUST keep each view's statements as data for it.
- **FR-014**: `specifications/fbl/structurizr.fbl` MUST state `place: end` for persons and software systems and `empty: keep` on `name`, its fixtures still passing.

### Key Entities

- **Declared binding**: an FBL binding whose rules state what is read and written, with no persistence plugin.
- **Conformance case**: a document, its steps, and what each step must produce, recorded from a module.
- **Recorded gesture**: one step of a case, in ATD §2.3's terms.
- **Not-supported list**: the fixtures the desktop's conformance run names and does not run, each with its reason.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: All 56 fixtures added by FBL 0.10 to 0.13, and any added until the plan is written, pass on the desktop host (1 passes today).
- **SC-002**: Every case of the 10 descriptions of story 2 passes `atd validate` under FR-012's comparison, every write byte-identical, apart from differences listed by name as a module's quirk (0 pass today).
- **SC-003**: Every case of the 4 descriptions of story 4 passes `atd validate` with no persistence plugin registered (0 pass today).
- **SC-004**: No recorded case step carries a module's target string, and `atd record --check` passes.
- **SC-005**: Every existing test and parity golden of the desktop host stays green, and a document opened by a person draws and saves as before.
- **SC-006**: `atd validate` gives the same result natively and through the WebAssembly module for every description this feature changes.

## Assumptions

- The modules stay the reference, so a difference is corrected in the description or the engines, never in a case's expected result.
- The standalone host's bindings in `specifications/fbl/` are the starting point for the descriptions' bindings, as spec 066 intended.
- The remaining formats (SPARQL, Ansible, Helm, Azure Pipelines, MSBuild) get their own specification once this one shows the way, and T132 and T131 stay open until then.
- FBL's open work under spec 066 lands before the plan fixes the version FR-001 names.
- Story 4's constructs are those found when T149 was attempted on 2026-10-27; the plan may find more.
