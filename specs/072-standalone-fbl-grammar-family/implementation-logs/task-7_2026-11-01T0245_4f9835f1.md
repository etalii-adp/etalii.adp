# Implementation Log: Task 7

**Summary:** The grammar family reads and writes FBL 0.13's `split` slot, with the three FBL 0.11 constructs it uses: `escape` on a `{node}` slot, `create` with `emit` and `after`, and many `{node}` slots (standalone PR #788, merge `4d16ac1`; tasks taken from etalii.adp `4696ce0`).

**Reading** (`Files/Grammar/SplitItems.cs`; `GrammarFamily.ReadItems`, `ReadMany`, `ReadNode`):

- A value is cut at its `split`, from the left. Each piece is trimmed of Unicode White_Space, and an empty piece is no item: `" Extra ,More,, "` holds `Extra` and `More`, `""` holds none, and `"Existing System"` holds one.
- Escapes are resolved per item, after the cut.
- The items of every node the slot reaches follow each other in document order.
- A `many` slot without `split` reads each node as one item.
- `BodyReading` asks the family's `many` for `{node}` slots.

**Writing** (`GrammarFamily.WriteItems`, `RemoveItems`, `AddItems`, `InsertSlot`; `Planning/ListDifference.cs`):

- A set writes the longest-common-subsequence difference of the old and new lists:
  - a changed item is a `replace-value` of its span, escaped;
  - new items are an `insert-key` of `separator` plus the values, right after the last item kept;
  - a run of removals after a kept item is a `remove-key` from that item's end to the run's end;
  - a run at the start of a node is a `remove-key` from the run's start to the next kept item's start;
  - a node whose items are all removed is a `remove-key` of the node and the white space before it;
  - where no node holds an item, the new items are a `replace-value` of the last node's value;
  - where no node exists, `create.emit` is written by one `insert-key` right after the first present `create.after`.
- `ListDifference.CommonSubsequence` is now shared with the `lines` family.
- Every write goes through the read-again check, with the read-back of a list compared as a multiset (see T008's report). An item that holds its own split would not read back, so it is refused.

**Loading** (`Documents/BindingReader.cs`, `FblModelTypes.cs`, `GrammarChecks.cs`):

- `escape`, `split`, `separator` and `create.after` are read.
- Each of these is refused where it stands:
  - a `split` beside `items`, on a slot of another family, or holding the escape's `with` or `quote`;
  - an `escape` or a `create.after` outside the family;
  - an `after` that names no other attribute of the rule.
- `FblBinding.CheckManyAttributes` refuses a `split` on an attribute the tool type declares single-valued.

**Fixtures:**

- `grammar-split-slot` passes byte for byte, with each step's undo.
- `refused/split-escape-collision.fbl` is refused at its `split`, and loads with `,`.
- `refused/split-not-many.fbl` loads. `CheckManyAttributes` refuses it given the causal loop's `Loop.title` as single-valued.
- `fixtures/structurizr-split-tags/` is not vendored (11.8).

`Pending`, which is empty now, was removed with its guard. InspectCode reports an empty set that is never updated, so T008's removal came one task early.
