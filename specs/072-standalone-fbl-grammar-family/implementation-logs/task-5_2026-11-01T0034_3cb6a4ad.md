# Implementation Log: Task 5

**Summary:** A body of the grammar family is read in part when its binding gives `recover` (standalone PR #786, merge `bebe195`; tasks taken from etalii.adp `4696ce0`).

How a body is read, unit by unit:

- `GrammarBuild.ParseUnits` parses each unit with an interactive parser from `recover.unit`.
- It keeps the parser's state before each token. A token the parser cannot shift, which may first make it reduce, then does not hide whether the unit ended: a lexer failure past the last token's start means that token was shifted.
- Where reading stops, the text is skipped from the unit's first token to the end of the first `sync` token lexed from there. `Files/Grammar/GrammarScanner.cs` lexes it with every terminal, by ATD 3.6's longest match, then priority, then a string terminal before a pattern, passing over characters no terminal matches.
- When no `sync` token follows, the text is skipped to the end of the body.
- The skipped text is kept as one leaf that binds nothing. It is reported once as `fbl.unparsed-text`, a warning, from where reading stopped to the end of the skipped text.

Without `recover`, a body that does not read stays unreadable at the failing token. `w3c-turtle-grammar-partial` is read, and its edits come with T006.

`Grammar/GrammarRecovery.Tests.cs` has 14 tests, each seen to fail under sabotage. One of them, `SkippedTextIsLexedByTheLongestMatch`, was added after a shortest-match sabotage first went uncaught.

The final gates' format and InspectCode findings were cleared: an unneeded using, a qualified name, a repeated default argument, a span copied by hand, and two comparisons a pattern merges. One timing-sensitive CausalLoop test (`Reload_DuringItsOwnSaves_NeverReplacesTheDocumentWithWhatAPublishLeftBehind`) failed once while another build ran beside it. It passed three times alone, and the whole suite passed on the rerun.
