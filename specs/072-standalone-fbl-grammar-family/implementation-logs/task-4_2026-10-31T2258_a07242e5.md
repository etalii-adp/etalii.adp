# Implementation Log: Task 4

**Summary:** A body of the grammar family is read (standalone PR #785, merge `628e698`; tasks taken from etalii.adp `4696ce0`).

`Files/Grammar/GrammarParser.cs` decodes the body once, with a table from UTF-16 positions to bytes. It parses with EtAlii.Lark's contextual lexer and builds the tree ATD section 4.5 shapes, over byte spans:

- A node's span is its container span, including the tokens the tree leaves out.
- A node that matched no token has no span, and an optional part that matched nothing is an empty part.
- Every token the lexer cut is a leaf. It is recorded by a lexer callback on each terminal of a parser loaded from the built one.
- An ignored token holding a character other than whitespace is a comment.

`Files/Grammar/GrammarFamily.cs` does the reading:

- It reads entries by selectors and gives CEL a node's `type`, `text` and `children`, an empty part being null.
- A `{node}` slot is read as the text of the first node it reaches or, with `match`, its group `value`. A text `match` does not match is read-only and absent (research R8).
- An entry's line span runs over the comment lines directly above it and the comment after it on its last line.

`w3c-turtle-grammar`'s reading, byte coverage and unchanged save run.

One bug was found and guarded: a statement whose last token is its line ending had no line span. `ALeadingCommentAndATrailingComment_AreInTheEntrysLineSpan` was seen to fail first.

Two follow-ups came from the final gates:

- The existing guard `SaveResultIsNeverDiscarded` read `Lark.Save`, which writes the built parser to a stream so it can be loaded again with lexer callbacks, as a dropped store save. `Lark` now stands among its receivers whose `Save` returns nothing by design, with that reason.
- InspectCode reported a redundant cast, which was removed.

The four gates exited zero (18,389 tests, 0 failed), and inspect.sh is clean.
