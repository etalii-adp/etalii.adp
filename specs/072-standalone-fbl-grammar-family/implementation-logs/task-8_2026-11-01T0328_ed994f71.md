### What the work found unclear, as candidate changes for etalii.adp

- **Research R8, FBL 0.9 section 5.2.** FBL does not say what a `{node}` slot reads when `match` does not match the node's text. The library reads such an attribute as absent and makes the slot read-only, so the entry's bytes are kept. A sentence in 5.2 would settle it for every host.
- **FBL section 15.1 against this spec's Requirement 8.1.** Since 0.11, section 15.1's last paragraph says a host that supports the `grammar` family only at 0.9 treats a binding using a 0.11, 0.12 or 0.13 construct of the family as one whose family it does not support: it opens read-only, with the reason. Requirement 8.1 says such a binding loads with section 2.7's warning, the unknown construct ignored. The library follows the spec, which is 8.1. It also now reads `split` and three 0.11 constructs, but not `pad`, `recover.nested` and the rest, so it is neither a 0.9-only host nor a full 0.13 one. Section 15.1 could say what a host reading part of a newer version does; until then, 8.1 is the one to amend if read-only is wanted.
- **FBL section 6.3, an item added in the middle of a split list.** Section 6.3 writes every new item after the last surviving one, so a set that inserts in the middle does not read back in the order given. The library compares the read-back of list attributes as a multiset, which section 6.4's read-again check does not state.
- **FBL section 6.3, `next-sibling`.** It has no anchor in a `grammar` body except the entry an `AddAfter` names. Without one, the library places the add as `after-last`. Section 6.3 could say so.
- **FBL section 4.9, *Reading in part*.** It does not say whether the read-again check may refuse an edit that leaves more text skipped than before. The library refuses it, as defence in depth. The check could be named in section 6.4.
- **This spec's Requirement 10.3 names pull request A as FBL 0.10.** It merged as 0.11, because B (Databricks) merged first and took 0.10, as spec 066's tasks allow. A small amendment of 10.3's wording would keep the record right; the report above uses the merged numbers.
- **Research R12's refusal sentence.** It reads "The new <attribute> would not read back from the <title> text." The library writes "… would not read back from the text.", because a binding's `title` is optional (`FblBinding.Title` is nullable), and the conformance runner compares no host sentence. This is a departure from the plan, not from FBL. R12 could be amended to the sentence the library writes.
- **ATD sections 3.5, 3.6, 4.1, 4.4 and 4.5.** Nothing was found unclear that EtAlii.Lark 0.4.0 did not already settle. One point only: section 4.5 does not say whether an empty optional part has a span. The library gives it none (Requirement 4.2 says a node that matched no token has no span), and the section could repeat that.
