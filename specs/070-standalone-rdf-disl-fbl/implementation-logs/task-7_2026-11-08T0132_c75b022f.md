# Implementation Log: Task 7

**Summary:** Task 7 gives the RDF family's one store an RdfBody and adds the persistence plugin net.etalii.adp.w3c.turtle (RdfTurtlePlugin and RdfTurtleReading), which reads the body through w3c-turtle.fbl.
- **Elements:** its Triple, Prefix and Base elements are the parser's triples, prefixes and base, in order.
- **Spans:** spans are UTF-8 byte ranges that count a byte-order mark. A value written once for several triples has no span, and a token two triples both spell is the span of neither.
- **Findings:** findings are RdfValidator's five rdf.* findings.
- **Unreadable bodies:** a body that does not parse is unreadable, with today's one finding, and RdfBody.Plan refuses with "<file> could not be read, so nothing can be edited until it can: …".
- **Plan:** the plugin's own Plan refuses everything in RdfTurtlePlugin.PlanRefusal, because commands still write through RdfWriter (Q5).
- **Template:** the template is the RDF graph's starter.
- **CEL functions:** rdfLocalName, rdfDisplayName and rdfResolveTerm read the diagram's Prefix and Base nodes as RdfProjection.Display and RdfTermInput.Resolve do, and RdfDefinitions now loads with them.

Other changes:
- **Store hook:** the shared LifecycleDocumentStore gained a protected Locate(path, body) hook, called at its four points (read, unavailable, save, edit on current), so a body knows its file name, its syntax (RdfSyntax, standing in for gap 5) and its refusal sentence.
- **Handlers:** RdfEditHandler splices body.Lines as before and then marks the body changed, so it is read again.
- **Readings:** the four readings share the one body, one edit and one undo of the project history.
- **Transcripts:** the transcripts are unchanged and none was regenerated.

Guards and gates:
- **Perturbations:** each new guard was seen to fail against a perturbation. P3 (double-claim removal) first failed nothing, so it gained AToken_TwoTriplesBothSpell_IsTheSpanOfNeither.
