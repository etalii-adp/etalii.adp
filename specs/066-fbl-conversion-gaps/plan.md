# Implementation Plan: FBL 0.10, What the C4, Databricks and Wardley Map Conversions Wait On

**Branch**: `features/066-fbl-conversion-gaps-plan` (planning); the implementation's branches are named in *Delivery* | **Date**: 2026-10-29 | **Spec**: [fbl-conversion-gaps.spec.md](fbl-conversion-gaps.spec.md)

**Input**: the specification, approved by the maintainer on 2026-10-29, who asked that the work proceed after his review, with its clarifications of 2026-10-27 (Q1: Structurizr DSL and `.owm` in the `grammar` family; Q2: every gap, the stand-ins included; Q3: a `view` that names nothing opens empty and in silence).

## Summary

FBL gains what the three standalone conversions' second stages wait on, in three pull requests to etalii.adp, one per user story, each a minor version in the order it merges (research R1). Pull request A extends the `grammar` family (FBL 0.9, section 4.9) for Structurizr DSL and for what the Wardley map shares with it: comments after a brace, a statement or across lines owned and kept, recovery inside blocks, escapes, absent and positional parts written and removed, a block written around a first child, views of a `grammar` binding with statements read for the selected view only, a view block that can be added, a read-only value gathered from two places, and the legacy layout's comparison, number form and pruning; `structurizr.fbl` is rewritten in the family with a grammar beside it, and `structurizr-open-block` passes unchanged. Pull request B lets one `yaml`/`json` binding serve the Databricks bundle, job and pipeline readings (`origins` on rules, a resource capture per origin, one model per origin of one open body), and states flow-sequence inserts, refusal sentences, a nested mapping written by an add, a secondary slot and `{key:lower}`, with a new `databricks.fbl`. Pull request C gives the `.owm` format a grammar and a binding, `wardley-map.fbl`: a next-line brace, trailer segments in any order and as sets, annotation positions as structured items, the legacy identities file as the array it is, identity kinds, a stored id per holder of a repeated key, and an identity entry that follows its key. Every construct defaults to FBL 0.9's behaviour. The schema, examples, fixtures, validator, ATD's Appendix C and the companions change in the same pull request as the prose (constitution II; FR-030 to FR-035). The FBL library code lands in the hosts under their own specifications, as the specification's *What this feature is not* says; the plan records which standalone task each pull request unblocks.
