# C4 container diagram (`c4/container`): what DISL does not express

This file accompanies [`c4-container.dis`](c4-container.dis), the DISL specification of the C4 container diagram as the standalone ADP implements it. The `.dis` holds everything DISL can say: the C4 metamodel, the notation, the toolbox, the forms, the rules as CEL, the layout and the persistence. This file holds everything else, each point tied to its evidence.

Evidence links point into [etalii.adp.ide.standalone](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692) at revision `b2a2692` (2026-09-30), where the six C4 diagram types share one module under `src/diagrams/c4/`. "Req n.m" is an acceptance criterion of the approved `c4-diagrams` specification (approved 2026-08-24; its documents were later removed from the tree, and survive as approval snapshots under `.spec-workflow/approvals/c4-diagrams/.snapshots/`).

The six C4 `.dis` files are deliberately self-contained and nearly identical: every C4 diagram type is one view over the same shared model, and the types differ only in the view they bind ([`ServiceCollection.AddC4.cs:21-30`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/ServiceCollection.AddC4.cs#L21-L30)). The sections marked *shared* below say the same in all six companion files; the sections marked *this type* are specific to `c4/container`.

## Files and registration (*shared*)

DISL describes one diagram per document. The C4 types do not work that way, and nothing in DISL's `persistence` can say how they do:

- **Two files, and the model is shared.** A C4 diagram on disk is a registration `<name>.adp` plus a Structurizr DSL document `<name>.dsl` that holds the model and all its views (Req 2.1). All six types claim the `.dsl` extension ([`Diagram.cs:22`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/Diagram.cs#L22)), and several `.adp` files may point at one `.dsl`, which is "model once, view many" (Req 2.4). The `.dis` declares `persistence.format: plugin:net.etalii.adp.c4.structurizrDsl` and a split into `{name}.dsl` plus `{name}.layout.json`; it cannot declare that the `.dsl` is shared by several diagrams, of different types, at once.
- **The registration format.** Line 1 is the type's MIME line; the next lines may carry `body: <path>` (relative to the registration's own folder) and `view: <key>`. The session reads at most eight lines after the MIME line, skips blank ones, stops at the first line that is neither `body:` nor `view:`, and treats an empty `view:` as none ([`C4SessionFactory.cs:44-82`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4SessionFactory.cs#L44-L82)). Writing a new registration emits exactly `<mime>\nbody: <relative path>\nview: <key>\n` ([`AddC4ViewCommand.cs:71-73`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/Commands/AddC4ViewCommand.cs#L71-L73)).
- **Which view opens.** The view named by `view:`, matched case-insensitively ([`C4Parser.cs:29-30`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L29-L30)). Without a registration, the document's first declared view (Req 2.6, [`C4Session.cs:140-152`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Session.cs#L140-L152)). A `view:` naming a key the document does not declare opens nothing: the canvas is empty and only the log says why ([`C4Session.cs:154-165`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Session.cs#L154-L165)).
- **One shared store.** All six types share one document store and one mapper, so an edit made through one view reaches every open view of the same model ([`ServiceCollection.AddC4.cs:58-63`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/ServiceCollection.AddC4.cs#L58-L63), [`C4Session.cs:6-17`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Session.cs#L6-L17)).
- **Which type owns a `.dsl`.** The view kind a session shows comes from the `.dsl`'s view, not from the MIME type of the registration that opened it ([`C4SessionFactory.cs:6-11`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4SessionFactory.cs#L6-L11)). A `c4/context` registration naming a container view shows a container view.
- **Adding a view.** `AddC4ViewCommand` appends a view block before the closing brace of `views` and writes the `.adp` beside it; it refuses when the key is taken, when there is no `views` block, or when there is no software system to scope to, and removes the view again if the registration cannot be written ([`AddC4ViewCommand.cs:27-85`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/Commands/AddC4ViewCommand.cs#L27-L85)). The new view is scoped to the first software system (the first container for a component view) and gets `include *` and `autoLayout lr` ([`AddC4ViewCommand.cs:176-194`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/Commands/AddC4ViewCommand.cs#L176-L194)). There is no UI that issues this command yet; Req 2.7 asks for "Add view" on `.dsl` files.

## The Structurizr DSL subset, and what survives a round trip (*shared*)

The `.dis` names the format `plugin:net.etalii.adp.c4.structurizrDsl`. What that plugin reads and writes is:

- **Byte-preserving.** The parser reads only what ADP models and ignores the rest, and the document keeps its own text, so unmodelled constructs (`!docs`, `!adrs`, `properties`, `url`, `theme`, `branding`, `terminology`, and so on) survive untouched (Req 3.3, [`C4Parser.cs:33-43`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L33-L43), [`C4Parser.cs:276-287`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L276-L287), [`C4Parser.cs:317-326`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L317-L326)). An edit rewrites one argument of one line and leaves every other byte alone (Req 3.2, [`C4Commands.cs:29-61`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/Commands/C4Commands.cs#L29-L61)).
- **Element declarations.** `[identifier =] keyword arguments... [{]` for `person`, `softwareSystem`, `container`, `component`, `deploymentNode`, `infrastructureNode`, `containerInstance` and `softwareSystemInstance`, case-insensitively ([`C4Parser.cs:47-57`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L47-L57), [`C4Parser.cs:166-172`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L166-L172)). Argument positions differ by keyword: a person and a software system take name, description, tags; a container, component and infrastructure node take name, description, technology, tags; a deployment node takes name, description, technology, tags, instance count; an instance takes the referenced identifier then tags ([`C4Parser.cs:444-467`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L444-L467)).
- **Tags.** A tag argument is split on commas and trimmed; a `tags "A" "B"` line inside an element's block adds more ([`C4Parser.cs:262-273`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L262-L273), [`C4Parser.cs:469-470`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L469-L470)). Relationship tags are *not* split: only a sixth token is read, as one tag ([`C4Parser.cs:239`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L239)), and a relationship declared inside an element block (`-> destination ...`) gets no tags at all ([`C4Parser.cs:249-259`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L249-L259)).
- **Relationships.** `source -> destination "description" "technology" "tags"`, at model level or inside an element's block with the element as source ([`C4Parser.cs:231-260`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L231-L260)). A relationship has no DSL identifier; its id on the wire is `source->destination@line`, so it changes whenever lines above it are inserted or removed ([`C4Element.cs:63-64`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/_Model/C4Element.cs#L63-L64)).
- **Identifiers.** Case-insensitive throughout ([`C4Parser.cs:24-26`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L24-L26)). An element declared without `identifier =` gets `<kind>_<name letters and digits>_<n>`, where n counts such elements in document order ([`C4ParseState.cs:61-70`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4ParseState.cs#L61-L70)); those ids are not stable across edits above them. `!identifiers hierarchical` is not supported: dotted identifiers resolve to nothing ([`C4DocumentFactory.cs:91-95`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4DocumentFactory.cs#L91-L95)).
- **Not elements.** `group` is transparent (its children belong to what contains the group) and `deploymentEnvironment` records nothing on its elements ([`C4Parser.cs:219-228`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L219-L228)), so no element knows which environment it is in.
- **`!include` is noted, not followed.** Anything declared in an included file is missing from the model, and a warning says so ([`C4Parser.cs:90-97`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L90-L97), [`C4RuleSet.cs:67-75`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4RuleSet.cs#L67-L75)). DISL has no construct for "a file this document refers to but the tool does not read", so the rule is not in the `.dis`.
- **Block comments** are skipped while parsing and kept in the text ([`C4Parser.cs:105-142`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L105-L142)).
- **Styles are not applied.** The `styles` block's `element "<tag>"` headers are recorded, but the properties inside them (`background`, `color`, `shape`, `border`) are never read ([`C4Parser.cs:422-435`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L422-L435)), so `C4Theme.Apply`, which would lay a document's style over the default theme ([`C4Theme.cs:84-118`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Theme.cs#L84-L118)), never changes anything. Req 4.8 asks for the palette to be overridable per model; the `.dis` states the default theme only.
- **Views.** The view keywords, and the argument shapes each takes, including the default key when the key is omitted ([`C4Parser.cs:328-352`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L328-L352)); `include`, `exclude`, `title` and `autoLayout <direction> [rankSeparation] [nodeSeparation]` inside a view ([`C4Parser.cs:378-402`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4Parser.cs#L378-L402)).
- **Placeholder text on add.** A new element is written as `<identifier> = <keyword> "<Name>" "Describe <Name>."`, plus `"Technology"` for a container or component, so it does not arrive with a warning ([`C4Placement.cs:225-244`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/Commands/C4Placement.cs#L225-L244)). Its identifier is the name's letters and digits with the first lowered, prefixed with `_` when it starts with a digit, and numbered `web`, `web2`, `web3` against clashes ([`C4Placement.cs:190-223`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/Commands/C4Placement.cs#L190-L223)). Adding a child to a one-line element gives that element braces, and undoing the add takes them away again unless something else has been written inside ([`C4Placement.cs:110-161`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/Commands/C4Placement.cs#L110-L161)).
- **New documents.** A new document is a workspace named after the file, with one software system of the same name as the scope and one view of this type with `include *` and `autoLayout lr` ([`C4DocumentFactory.cs:31-102`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4DocumentFactory.cs#L31-L102)). The identifier is the file name with everything but letters, digits and `_` replaced by `_` ([`C4DocumentFactory.cs:104-118`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4DocumentFactory.cs#L104-L118)).

## What a view shows (*shared*)

- **Membership.** A view shows the elements it names with `include`, plus, for `include *`, every element of the kinds the view permits, minus `exclude`, without duplicates ([`C4RuleSet.cs:404-431`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4RuleSet.cs#L404-L431)). `include *` ignores the scope: it takes every permitted element in the whole model, not only those around the scope element as Structurizr does. DISL viewpoints filter by type, which is what the `.dis` states; the explicit include list and the scope-free wildcard are behaviour of the plugin.
- **Relationships are elevated.** A relationship whose ends are not on the view is drawn between their nearest ancestors that are; two ends under the same drawn element are dropped; several relationships collapsing onto one pair draw one line, carrying the first one's label ([`C4ElementMapper.cs:282-333`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4ElementMapper.cs#L282-L333), [tests.md](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/tests.md#L467)). DISL relations connect the elements they name; it has no notion of drawing a relation at a coarser level.
- **Relationship label.** Drawn as `description [technology]`, or the description alone, at the midpoint, 6 above the line; the in-place editor opens with the description alone ([`C4Canvas.tsx:232-244`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/client/C4Canvas.tsx#L232-L244), [`C4Canvas.tsx:161-175`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/client/C4Canvas.tsx#L161-L175)).
- **Title.** Every view carries a title above the canvas: the view's own `title`, else `Container diagram for <scope name>`, or `Container diagram` ([`C4ElementMapper.cs:119-156`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/backend/EtAlii.Adp.Diagram.C4/C4ElementMapper.cs#L119-L156), [`C4Canvas.tsx:295-300`](https://github.com/etalii-adp/etalii.adp.ide.standalone/blob/b2a2692/src/diagrams/c4/client/C4Canvas.tsx#L295-L300)).
